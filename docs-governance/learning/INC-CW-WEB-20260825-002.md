## Executive finding

The incident was not one isolated HTML defect. It was a chain failure across baseline authority, approval-state interpretation, review transport, visual integration, deterministic validation, recovery discipline and response/execution order. The current `web-workstream-control` Skill was verified against the archived ADDITIVE_ONLY hardening package and was not found to have silently degraded. The dominant failure was inconsistent execution of already-existing controls, compounded by missing enforcement at system level.

The recovery principle is therefore **preserve-and-repair, not rebuild**. Exact historical REV artifacts remain recoverable. REV25 restored the reconciled 04A–17 hub from the complete REV21 source. Later REV27–REV32 continue as immutable descendants; production remains untouched.

## Preventive controls effective immediately

### Source and baseline
- Every material REV is immutable and receives a unique semantic label.
- Exact raw HTML in Drive + SHA-256 + sidecar + raw-byte readback is mandatory before a review frontier can close.
- A transport wrapper may never share the same candidate identity as a materially different full candidate.
- A standalone review HTML must be tested as a standalone surface; bundle-relative resource success does not prove standalone resource success.

### Approval and gating
- `SOURCE_VALIDATED`, `BROWSER_RENDER_VALIDATED`, `CHAT_VISUALIZER_USER_VISIBLE`, `ROLLING_PROGRESS_READY`, `USER_APPROVED`, and `PROMOTED` remain separate states.
- Rolling Progress Preview is context only, never the formal approval surface.
- No “final” claim from a broad static PASS; each user-reported defect requires its own acceptance regression.
- Final-IA coverage is reconciled from the exact current candidate before a completeness percentage or closure claim.

### Visual integration and asset integrity
- CSS dependency ancestry is part of preservation. Scoped selectors must have a matching ancestor after integration.
- For changed visual components, browser QA checks computed styles, layout/overflow and responsive behavior, not only source presence.
- Text/icon contrast is measured when foreground/background colors change or conflict is reported.
- Semantic icons receive a deterministic marker so the intended symbol cannot silently regress.
- Protected image sections require image count + alt + href count + exact asset-byte/source checks and actual rendered load checks on the delivered review surface.
- Remote release media is tracked separately from locally embedded protected review media; known remote Wikimedia dependencies must be localized or explicitly accepted before production.

### Link integrity
- Internal anchors must resolve to a unique target before a candidate can advance.
- Non-link deltas preserve href values exactly.
- External reachability uses `VALID`, `FETCH_INCONCLUSIVE`, and `CONFIRMED_DEAD`; crawler inability never silently becomes a content edit.

### Execution discipline
- Incremental Control `FAST_WITH_CHECKPOINTS` governs execution, not just response formatting.
- Execute all reversible authorized actions before writing the response.
- Coherent batches are preferred over micro-REV churn.
- At the first contradiction: component freeze, causal diagnosis, preserve unrelated validated state, targeted repair.

### Tool/write and QA discipline
- Before any mutation, record exact action + target ID/path; after the write, read back before issuing another mutation to the same class of target.
- Duplicate write attempts are assistant-caused rework and must be logged rather than hidden.
- Repository review transport moves only after the complete staged tree validates.
- QA/verifier scripts must be read-only and idempotent against persisted deliverables. Artifact building and artifact verification are separate commands; a verifier may not rewrite the file whose hash it is validating.
